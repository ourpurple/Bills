# P2 / P3 邮箱与资料导入

更新时间：2026-10-09。已完成本地自动化和页面联调；真实服务商 / ARM Docker 验收仍待完成。

## 1. 本阶段的边界

P2 部分只收信、保存原始资料、用成熟库准备纯文本，**不识别银行 / 金额 / 日期 / 交易字段**。P3 已接入可配置大模型 API、账户匹配、候选核对与发布；默认关闭模型与自动发送，文本准备本身不会生成账单。P1 人工账单继续可用；Android 和实际通知仍未开发。详见 `model-guide.md`。

通用转换只使用 Python email、BeautifulSoup、pypdf。邮件头日期仅用于来源记录与候选范围筛选，不是账单日 / 还款日。没有本地银行模板、字段正则、语义解析器或模型失败后的规则兜底。

## 2. 启动及主密钥

API、管理网页和 worker 三者需分别启动；Docker Compose 已包含三个对应服务。先迁移数据库，再启动服务。

在后端目录使用 `python -m app.cli generate-key` 生成 Fernet 密钥，安全填写 `BILLS_MASTER_KEY`。API 与 worker 必须一致。无密钥可以上传资料，但无法创建邮箱 / 模型凭证。密钥不会由服务自动生成或回显。

- 邮箱密码 / 服务商授权码加密存入数据库；列表只返回“已配置”。编辑时留空表示保持原凭证，密码首尾空格不被剥离。
- **替换主密钥不是安全轮换方式**：旧凭证会无法解密。目前未实现轮换；更换前需安排重新录入所有邮箱 / 模型凭证及私人替换配置。丢失密钥不能恢复原凭证。
- 密钥单独安全备份；原邮件、纯文本资料和数据库都属于私人资料，原资料不是 Fernet 加密文件，应保护 VPS / 卷与备份权限，异地副本应加密。

## 3. 配置多个邮箱

后台进入「邮箱与导入 → 邮箱配置 → 新增邮箱」。每个邮箱独立配置名称、地址、主机、端口、协议、TLS、登录用户名和密码 / 授权码。

- IMAP 推荐：隐式 TLS 通常端口 993；STARTTLS 常见 143。
- POP3：隐式 TLS 通常 995；STARTTLS 常见 110。具体以服务商配置为准，不自动猜测。
- 强制证书校验，不提供明文连接或跳过 TLS 的选项。服务器地址只接收域名 / IP，不是 URL。阻断回环、内网、保留地址及混合 DNS 答案，固定已验证公网 IP 连接，TLS 仍按原主机名校验。
- 首版只支持密码 / 授权码；仅允许 OAuth 的邮箱不在本阶段支持范围。
- IMAP 文件夹使用 ASCII 或服务商提供的 modified UTF-7 名称；POP3 仅 INBOX。
- 默认每 30 分钟、首次最近 90 天。开启后 worker 自动排队。可停用邮箱保留所有历史资料。
- 发件人和主题“包含词”只决定候选收信，不推导任何账单业务字段。每组内部任一词命中即可，两组之间同时满足；空组不限制。**留空可能接收其他私人邮件**，建议配置明确的发件人 / 账单主题词。

先点「测试连接」，在任务队列看实际结果，再「立即同步」。排队成功不是收信成功。认证、证书、UIDL 不支持等问题暂停对应邮箱；修正配置后测试成功可解除暂停，但不会自动启用已停用的邮箱。

## 4. 同步身份、补扫与恢复

- IMAP 用邮箱配置身份 + UIDVALIDITY + UID；只读 SELECT、BODY.PEEK，正常读取不改变已读，不删除或移动原信。
- POP3 必须支持 UIDL，持久身份不采用会话序号；TOP 不支持时，在大小限制内用 RETR，不发 DELE。不支持 UIDL 明确停止自动同步。
- 修改服务器 / 协议 / 用户名 / 文件夹会建立新同步 epoch 并清游标，旧资料保留。普通字段修改也更新配置版本，旧任务不能使用过时配置提交结果。
- 修改筛选词不会自动重取全部历史；使用「历史补扫」显式选择开始 / 结束日期。日期范围按 Asia/Shanghai 解释，结束日包含；IMAP 服务端搜索结合来源日期筛选。未知 Date 明确留待处理，删除于服务器的历史邮件无法保证找回。
- POP3 没有增量日期检索保证，会列出 UIDL 并跳过已记录身份；补扫可能再次下载候选。IMAP UIDVALIDITY 改变时重建扫描身份，不把旧 UID 当作新邮件继续使用。
- 每批默认 20 封，单次同步预算 120 秒，未完任务续排，避免单个大邮箱独占队列。
- 获取失败先记录来源和重取任务，再提交游标；转换失败不重新收取已保存的正文。
- 原始资料按字节 SHA256 保存；输入按规范化内容指纹复用，跨邮箱仍保留各自来源，避免重复转换。这不是 P3 的业务账单去重，也不表示跨格式内容一定相同。

任务位于 SQLite，不使用 API 内存后台任务。领取 / 保存采用短事务，网络和文档转换不持有写事务。租约默认 180 秒、心跳续租、过期回收；旧 token 不能提交。可重试故障最多 3 次，指数退避；认证 / TLS / 格式不支持不盲目重试。手动重试生成新任务，旧失败记录保留。同一邮箱连接任务互斥；测试支持其他邮箱继续处理。

来源状态：`pending` 等待转换；`ready` 文本已准备；`partial` 有文本但存在警告；`unsupported` 不支持；`skipped` 候选筛除；`fetch_failed` 取信失败；`conversion_failed` 转换失败。

## 5. 上传、通用转换与安全预览

支持 `.eml`（最大 20 MiB）和文本型 PDF（最大 10 MiB）。后台上传先认证 / 校验 CSRF，保存原始资料并排转换任务。重复上传相同原文件返回同一来源。上传文件名仅用作展示，不作为存储路径。

- MIME 多部分内容、常见字符集；alternative 优先 plain，避免重复正文。
- HTML 去除脚本 / 表单 / 图片等，只保留纯文本，预览不渲染邮件 HTML、不执行脚本、不获取外链资源。
- 文本 PDF 用成熟库提取，单文件默认最多 80 页；不使用 OCR。加密、扫描、损坏 PDF、压缩包、不支持附件明确记录警告；有其他可用正文则为 partial，否则 unsupported。
- 单封默认输入上限 250,000 字符，超出截断并标记；附件最多 10 MiB，MIME parts、PDF stream 有限制。截断 / 部分准备资料在 P3 不会自动发布，须核对原件。
- 转换在独立子进程，默认 30 秒超时；Linux 限制子进程 CPU 与地址空间。Windows 本地验证只保证进程超时；Linux / ARM 限制效果待目标环境验收。
- 原资料和输入在数据库旁 `sources/raw/`、`sources/input/` 私有目录；可用 `BILLS_STORAGE_DIR` 改位置。默认总配额 1 GiB，达到配额明确失败，不静默丢资料。当前未实现自动清理 / 保留期任务，不要只删除文件而留下引用。

来源资料里的「安全预览」只有管理员可访问，设备没有邮箱、任务或私人邮件管理权限。显示的片段名为稳定编号，原上传文件名仍在来源中；内容指纹文件写入与数据库提交间中断后可安全重试。

## 6. 健康状态与验证限制

`worker_online` 表示最近心跳（默认 45 秒内，随轮询间隔增大），不是连接邮箱成功或任务全部完成。建议一个 worker；healthcheck 查询共享数据库近期心跳，不区分单个容器副本。API readiness 不依赖 worker，worker 暂停不阻止管理既有账单。`--once` 完成一轮后退出，心跳会短暂仍显示在线。

自动化测试用隔离临时 DB、合成文档、模拟协议服务；浏览器使用真实 API 和独立 worker。未使用真实邮箱 / 银行私人样本，不宣称服务商认证成功。仅密码认证可用性需分别验证；ARM 镜像、非 root 卷权限、PDF 限制和 HTTPS 仍需部署演练。

完整备份必须包含数据库、sources 目录和单独保存的主密钥。仅 SQLite backup 不能恢复全部来源资料。详见 deployment.md。

## 7. 文本准备后识别

来源 ready / partial 可手动点击「模型识别」；已有相同输入与配置版本则复用运行。强制「重新识别」可能产生新费用，先确认。模型配置启用但自动识别关闭时，不会自动发送历史资料；明确打开自动识别则会处理历史积压及新资料。候选在「模型与核对」检查后发布，不将邮箱同步成功或文本准备成功显示为账单识别成功。
