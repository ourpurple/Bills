# P3 模型识别与人工核对指南（0.3.0）

更新时间：2026-10-09。此版本完成本地合成数据验收；未接入真实服务商，未完成 13 家银行样本验收或 ARM VPS 部署验收。

## 1. 什么交给模型，什么留在本地

- 邮件正文和可用附件的账单摘要、银行、持卡人、卡片、日期、金额、交易字段和原文引用，只由 `/v1/chat/completions` 大模型提取。
- 本地只完成通用 MIME / HTML / 文本 PDF 转文本，验证模型 JSON / 字段 / 日期关系 / 金额精度 / 币种，检查引用是否出现在对应文本片段中，再匹配已有账户和执行入库规则。
- 无本地银行模板、字段提取正则、交易行解析、OCR 或失败规则兜底。模型不可用时，不会据正文自动生成正式账单；人工账单仍可录入。
- 引用存在不等于理解正确；模型可能给出错误但合法的数据。不能把 schema 校验、连接成功或自动化测试理解为银行账单已验证。

## 2. 启动与配置

先完整备份，迁移数据库到 `c38f14d7a902`，再启动 API、管理网页与独立 worker。API 和 worker 必须共用同一 `BILLS_MASTER_KEY`，用于加密模型密钥和已知私人文本替换列表。

后台「模型与核对 → 配置模型」：

| 配置 | 说明 |
| --- | --- |
| HTTP / HTTPS 基础地址 | 填供应商的基础地址，例如 `https://provider.example/v1` 或 `http://provider.example:8080/v1`；不是完整 chat/completions 地址。仅允许公网地址，建议 HTTPS；HTTP 会明文传输 API Key 和资料文本。HTTPS 验证证书，不允许重定向或本地地址 |
| 模型名称 | 服务商实际支持的文本模型名称；本地不猜测 |
| API Key | 首次必填；保存后不回显，后续留空保持原值 |
| 启用模型 | 默认关闭；打开允许手动识别，并不自动发送历史资料 |
| 自动识别 | 默认关闭；明确开启后，已准备的历史积压资料和新资料都可能被发送并收费 |
| JSON mode | 可选 `response_format`，仅在供应商支持时启用；无论是否开启都执行严格 JSON 输出校验 |
| 超时 | 默认 60 秒，可配 5–120 秒；整体请求时限包括握手、响应头及正文接收 |
| 输出 token 上限 | 默认 8192，可配 512–32768；输出截断记为失败，不发布残缺 JSON |
| 输入字符上限 | 默认 120000，可配 1000–250000；超过则截断并警告，禁止自动发布 |
| 每日调用上限 | 默认 50，可配 1–1000，按 Asia/Shanghai 日期统计 |
| 单任务调用上限 | 默认 2，可配 1–3；同时受持久任务尝试次数上限约束 |
| 输入 / 输出单价 | 可留空；按每百万 token 计，CNY / USD 分开估算；未知不当零 |

配置修改增加版本，旧配置执行中的任务不能提交候选。配置版本变更可能使相同资料再次识别，尤其自动识别已开启时；每日预算跨版本累计，不会因换配置重置。

### 连接测试

只发送固定 `{"ok":true}` 测试要求，不发送账单文本。测试可在模型开关关闭时进行，也占调用次数预算。查看任务是否成功，不把排队视为成功。测试仅证明接口兼容和连通，不能替代真实账单准确性验收。

## 3. 隐私和资料范围

手动 / 自动识别都会向选定的服务商发送通用转换后的文本。请确认服务商的留存和隐私政策，先上传脱敏样本。原邮件、转换文本和候选留在 VPS；它们不属于应用层加密文件，须保护磁盘与备份。

可配置**已知私人文本替换**：逐项输入明确知道的姓名等原字符串。发送前替换成不碰撞的占位符，在返回结构中还原。列表加密存储，不回显；编辑时可保留、显式替换或清空。

这不是自动脱敏检测：系统不会发现遗漏的完整卡号、身份证、地址或其它敏感信息，未列出的内容仍可能发出。避免使用过短或通用片段，替换可能影响模型理解；启用后用样本确认提取和账户匹配。

邮件视作不可信资料，固定系统提示禁止服从邮件内指令；请求不提供任何工具、数据库访问或密钥。拒绝工具调用响应。无法保证完全消除提示注入或模型误识别，人工核对仍必要。

## 4. 建议操作流程

1. 先配置真实对应的持卡人、分组、账户和卡片尾号；合并 / 独立还款依据账户配置，不让模型改变还款模式。
2. 在「邮箱与导入」上传脱敏 EML / 文本型 PDF，或同步已筛选的邮箱。等待文本已准备。
3. 点「模型识别」；持久 worker 排队调用，跳转「模型与核对」。同输入和配置 / 提示词 / schema 版本优先复用已有运行，跨来源保留各自归属。
4. 等待候选出现，打开核对档案：摘要与账户、模型原始提取与证据、安全纯文本原文、交易详单、修改历史。
5. 无匹配或多匹配时人工选账户，未知必填字段手动确认；核对本期应还、最低、账单日、到期日、币种与卡片归属。
6. 修改摘要或详单后先保存并填写说明，保留模型原始提取。存在警告时逐项核对并明确接受；未保存修改不能发布。
7. 发布创建已确认账单；相同账户 / 币种 / 账单日已存在账单时，查看差异，明确选择「相同」或「修订」。版本改变返回冲突，刷新再核对。
8. 发布 / 修订转到账单档案，可查看当前及历史详单。修订保留账单 ID、还款标记和计划关联；详单顺序和重复交易保留，不按日期金额去重。
9. 不应入库的候选填写说明后忽略。已发布 / 相同 / 忽略候选不能再次编辑或发布。

详单状态区分「完整」「部分」「未提供」。无详单不等于无交易；不得简单用消费明细合计代替银行本期应还。

## 5. 失败、预算与费用

- 超时、网络失败、部分可重试 HTTP 错误、无效 JSON / schema 和输出截断受有限重试约束；凭证 / TLS / 配置变更等不盲目重复调用。
- 调用前持久化预留记录，单模型资源锁防止并发请求；网络期间不持有数据库写事务，不阻塞邮件转换和人工管理。
- 崩溃 / 超时可能已被服务商计费。无法确认的调用记为未知，仍占每日预算；未知费用不从合计中伪造零。
- token 或单价缺失时费用 `null`；明确零单价可估为零。按币种单独累计已知估算，不是供应商最终账单，也不是硬金额预算。
- 强制「重新识别」会保留旧候选并可能产生新收费；已有运行中的任务仍共享。失败候选不会被自动调度无限重建，需明确人工重试或改变配置。
- 人工重试创建新任务，有新的单任务额度，但继续占同一日额度。连接测试也占额度。
- 超过预算后查看任务错误，调整前确认意图和供应商实际费用。日志 / 接口不回显密钥、供应商错误正文或请求账单内容；来源预览为管理员专用。

## 6. 自动发布：默认不要打开

只有使用真实脱敏样本验证过的**银行 + 来源类型（EML / 文本 PDF）+ 提示词版本 + 转换版本**才可显式登记为已验证格式。当前没有任何银行的真实格式被本项目自动认可。

即使已登记，自动发布还要求完整 ready 来源及输入、无校验 / 输入 / 证据警告、账户唯一匹配、必填字段完整且没有已有对应账单。调用结束在发布事务内再次检查来源准备状态。资料部分准备、截断、证据缺失或账户歧义均留待人工核对。

**自动发布只新建，不自动修订，不静默覆盖人工账单或还款关联。** 该格式配置只是一项管理员验证声明，不是自动识别到的精确银行模板指纹。银行更换格式时应关闭并重新验收；当前默认始终人工核对。

## 7. 当前限制和真实验收

- 单次模型输出最多 20 个账单摘要、每个最多 1000 笔交易，HTTP 响应限制 2 MiB；长详单尚未实现分块识别合并。输入或输出超限会明确警告 / 失败，不承诺全量解析。
- 通用输入不支持扫描或加密 PDF、压缩附件；HTML 预览只显示纯文本，不执行脚本或加载外链。
- 13 家银行是默认管理配置，不是 13 家银行模板验收。实际服务商的输出格式、模型名、token 和 JSON mode 兼容仍待验证。
- 自动化与浏览器测试只用固定合成模型响应，没有真实模型收费请求；测试 fixture 不进入生产 Docker。
- Android、实际提醒、真实邮箱 / ARM / HTTPS 和完整容器恢复尚未验收。

真实验收先关闭自动发送 / 发布，每家准备合并 / 独立账户、无详单 / 有详单、更正、重复、多币种和缺字段样本；逐字段对照原件，记录模型名、配置版本、提示词版本、准确性、token 和实际费用。通过代表性样本后再逐家扩展，发现差错只调整模型输入 / 提示词 / 输出约定，不加入本地银行解析规则。

## 8. 升级与备份

迁移新增六张模型 / 候选 / 详单表，不重写 P1 财务表。完整备份同时保存 SQLite 快照、`sources/` 和单独安全保管的原主密钥。更换主密钥不是轮换：旧邮箱 / 模型凭证与替换列表会无法解密；当前没有自动轮换工具。

降级 P3 会移除候选、调用和模型详单，虽然原财务表与还款不被重写，仍会失去 P3 记录；不要把测试迁移往返当作生产无损回滚。恢复及上线步骤见 `deployment.md`。


## 编辑 HTTP 地址、删除配置与部署更新

- 新增与编辑均允许公网 HTTP / HTTPS 地址，编辑时 API Key 留空会保留现有密钥。
- 页面或配置弹窗的「删除模型」需要二次确认；清除模型地址、名称、密钥和隐私替换文本，关闭自动识别并取消待发送任务。历史账单、候选和调用记录保留。已发送的请求无法撤回，但返回结果不会继续提交。
- 删除后可重新添加，API Key 须重新填写；配置版本继续递增，避免旧任务或缓存结果误用于新模型。
- 如果编辑仍报「仅允许 HTTPS 地址」，或页面仍显示「HTTPS 基础地址 / 仅连接公网 HTTPS」，说明运行环境未使用本次更新。Docker 部署须更新服务器源码并重建、替换 API、worker 和 gateway，仅重启旧容器不会加载新代码。

在服务器项目目录确认源码已更新后执行：

```sh
docker compose up -d --build api worker gateway
```

等待服务健康后强制刷新浏览器（Ctrl+F5）再试。不要删除数据卷，也不要重新生成主密钥。本地开发则重启后端和 worker，并刷新前端页面。
